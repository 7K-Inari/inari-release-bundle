# inari-release-bundle — Agent Guide

Release bundle for Inari: the core Helm charts (charts/inari-platform, charts/inari-server, charts/inari-console), ArgoCD Application definitions (gitops/), day-0 bootstrap (plan §6 #10, §9 M0). Formerly inari-helm-charts.

Stack: ArgoCD sync waves over Helm charts (chart releases as OCI)

## Key architecture constraints
- **Day-0 bootstrap: Inari must never require Inari to install** — scripted first-platform-cluster install lives here (§12.1/1).
- gitops/ composes: Keycloak (realm `inari`), PostgreSQL (CNPG), NATS, OpenFGA via ArgoCD Applications; inari-server/inari-console charts release from this repo; the inari-agent chart stays in its component repo. Everything publishes to the org-level namespace `oci://ghcr.io/7k-inari/charts` (§4.2).
- Backup/restore runbook coverage: PostgreSQL, OpenFGA store, Keycloak config, NATS — a tested restore is an M0 exit criterion (§9 M0, §12.1/1).
- `scripts/e2e/` owns the e2e assets (relocated from inari-server), organized per surface: `api/api_schema_e2e_test.go` (Go driver), `kubectl/kubectl-access.sh` (direct-access chain), `kubectl/kubectl-tunnel.sh` (gateway chain: kubeproxy + tunnel-agent + real apiserver over docker, builds sibling inari-server/inari-agent checkouts via `INARI_SERVER_DIR`/`INARI_AGENT_DIR`; runs non-blocking in the `e2e-nightly.yaml` `kubectl-tunnel` job), `lib/ui-proxy.mjs` (shared UI shim), `stack/` (golden-path Go suite — self-contained module, `go test -tags=e2e`; provisions the whole kind stack in-process AND asserts it: kind/hostPath/operators in `suite/provide.go`, dependency-layered concurrent helm installs in `suite/provision.go`, KC seeding + tenant/cluster/agent in `suite/seed.go`, assertion phases incl. HA disruption gated on `E2E_HA=1`, thin CLI-exec wrappers in `internal/`, e2e values trims in `testdata/`; `E2E_HANDOFF_PATH` at an existing file attaches assert-only. golden-path.sh was deleted in shell→Go migration phase 3) and `ui/` (Playwright Test suite — setup-project auth personas, page objects, `@p0 @smoke` access-tabs spec; personas + the inari-ui redirect whitelist are seeded by `ui/seed/seed-personas.mjs`; see `scripts/e2e/ui/README.md`). `scripts/e2e/README.md` is the suite map (incl. the flakiness-containment policy: gate runs `--grep @p0 --grep-invert @quarantine`, `ui/quarantine-issues.mjs` (ReportPortal-fed flake issues + 14/30-day expiry + the pinned quarantine-budget issue — `ui/report-flakes.mjs` was retired with the ReportPortal feed), and the full-suite nightly incl. `@quarantine` runs as the Argo CronWorkflow `e2e-nightly` (`gitops/e2e/argo-workflows/`)). The kind-era reusable `.github/workflows/e2e-stack.yaml` is retired; the Argo WorkflowTemplate `e2e-stack` (`gitops/e2e/argo-workflows/workflowtemplate-e2e-stack.yaml`) owns the whole stack leg — env re-convergence, seed, suite legs, JUnit → ReportPortal — and `release-e2e.yaml` is the thin gate that submits it (`mode=release`) and waits (plus the repo-native `server-integration` job); the non-blocking GHA `e2e-nightly.yaml` keeps only the quarantine sweep + the kubectl-tunnel scenario; Go-side quarantine is Ginkgo `Label("quarantine")` in `stack/suite/labels.go`, excluded by the gate filter `--ginkgo.label-filter=(p0||smoke)&&!quarantine` and included by the nightly's `p0||p1||p2` filter (same rule as inari-server's `flaky` build tag). `.github/workflows/release-e2e.yaml` gates Release PRs with them; the workflow still checks out inari-server at the pinned tag for the Go integration/api-schema suites. Never reintroduce e2e assets into inari-server.
